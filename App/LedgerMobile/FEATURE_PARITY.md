# iOS and mobile web feature coverage

This file records what the native app actually implements. Keep it aligned with
the code, not with a plan: every row states the current behaviour and points at
the source of truth. When a shipped feature changes, update this file in the
same change.

The production app is **local-only** (`docs/ios-local-first-ledger.md`). Hosted
features — remote authentication, Gmail automation, the agent workspace, web
push — stay out of scope by design, not as pending work.

| Ledger assistant (账本助手) | Chat over the local ledger with a model and API key the user picks (Anthropic, OpenAI, Gemini, DeepSeek and others, or a custom compatible endpoint), run on device by the PiG agent loop in LedgerCore. It queries with BQL, search, summary and account tools, and edits through list/read/edit/write/move/delete file tools (any non-hidden file in the ledger folder; binary files can be moved or deleted, not edited) plus bean_check on a private draft copy; a change card shows the per-file diff and validation result, and the write policy chosen in 助手设置 → 写入账本 decides what happens to it: 自动写入 (the default) commits a validated change at once through the shared prepare/validate/commit path, keeping file deletions and changes that cut more than 20 lines for the card and its 写入账本 button; 全部自动写入 commits every validated change; 每次确认 always waits for the button. Every write is its own commit and the 撤销 under the answer reverses it; a conflict with the ledger or a failed check always stops for the user. Statements can be attached to a conversation (CSV, Excel .xlsx/.xls, PDF, photos and screenshots), picked from Files, picked from the photo library, or dragged into the conversation from Photos, Files or another window: files are copied into runtime/agent-attachments, PDFs are read with PDFKit and scanned pages and images with on-device Vision OCR, the core parses tables, and reconcile_attachment matches statement rows against an account's postings to report missing, extra and amount-mismatched entries; save_attachment copies an attachment's original file into the ledger (for example documents/statements/); archive_statement files a bill's original where the 导入 page looks (transactions/<year>/documents/imports/, named by its period and channel), so a bill the assistant imported shows up in that channel's coverage and the archive list instead of only in the transaction file; fixes and saved files still go through the draft and the write policy, and the card shows binary files by size. A conversation is named by the model once it has two answers, from the first two exchanges, through the same small no-tools request as suggestions and recaps; a failed name stays unnamed and is tried again on a later answer, three tries in all, and with that toggle off, the first question names it. Earlier conversations are readable: list_saved_conversations and read_saved_conversation cover the records in runtime/agent-history (current conversation excluded), so a question can refer back to what was decided before, while balances and entries are still re-read from the ledger. Return on the software keyboard sends (a multi-line paste does not), Shift-Return adds a line on a hardware keyboard, unsent text stays with its conversation while the app runs, the view follows new content down until the reader scrolls up or opens the process line or a step in it (content growing past the bottom does not stop it; leaving the page at the bottom, 回到底部 or a new question resumes it; a conversation shorter than the page stays at rest at the top), and VoiceOver announces a finished answer. A running turn streams: the reply appears as it is written (an unclosed code fence reads as prose until it closes), and the reasoning and tool calls behind it fold into one collapsed line, 已运行 N 秒 · 思考了 N 秒 · 读取了账本 N 次 (the time and counts tick while it runs), with what is under way right now (the call running, or the reasoning's last line) on one line beneath it. Opened, the line lists every step in order: each reasoning block, expanding to its text, and each call going from running to done or failed with its duration and the first lines of its result or error, a tap adding its arguments and the result in full; the same line is saved with the answer and redrawn, collapsed, when the conversation is reopened (older saves show their tool list as before). Stop keeps the partial reply marked 已停止, and the next question continues from a transcript that includes it. The composer is one row at rest (attach, field, send) and grows a second row as soon as the field is tapped (or holds a draft, a question being edited, or an attachment chosen or being read), which stays until a question is sent, when the keyboard also goes down, with one chip for the model and thinking effort (a menu under each half); a small ring on that row shows how full the model's context is, with the token counts on tap. In a conversation with nothing asked yet the top bar's first button hides or shows amounts (the app-wide amount privacy); once there is a message, a running turn or a pending change it is 新对话. Each finished answer has 复制 (Markdown kept), 重新生成 and 分享 (hidden while amounts are masked) under it, and a long press on 复制 offers 复制为纯文本; answer and question text stays selectable; a code block has its own copy button. A pencil under a question is 编辑后重新发送, which puts the question in the composer under a 正在编辑第 N 个问题 banner. Regenerating or editing cuts the native transcript back to before the question (TruncateTranscriptJSON; the visible history is replayed when there is no transcript) and keeps the earlier answer or question as a version: a ‹ 2/3 › switch under the question or answer moves between versions, each with its own saved transcript, and the next question continues from the version shown. ## Deliberately out of scope

| Area | Why |
| --- | --- |
| Remote server authentication | Production composition creates local repositories only |
| Gmail automation | `performGmailRequest` requires a `LedgerRemoteGmail` repository, which local storage never provides |
| Agent workspace | Hosted ledger automation is outside the local-only product; the on-device 账本助手 covers asking and editing within one ledger |
| Web push notifications | The local app has no push service |
| Passkey login | Needs a paid Apple Developer team and associated domains |
| S3 storage provider | Not planned; iCloud Drive backups cover the need |

## Known gaps

These are real, verified against the code, and intentionally not presented as
finished:

- The Accounts list has **no keyword search**; it offers only the category
  filter bar. `DESIGN.md` describes a search field with separate expansion
  state, and that design is not implemented yet.
- `DESIGN.md` says accounts have "no category segmented picker". The shipped
  screen has the filter bar described above. `DESIGN.md` needs a decision:
  either the filter bar is the intended design and the sentence is stale, or
  the filter bar is unplanned work.
- Opening a ledger that uses an unlisted plugin or an external path fails with a
  compatibility error and cannot be opened read-only. This is the one item
  `docs/ios-local-first-ledger.md` still calls future work.
- App-host tests (SwiftUI rendering, bundled resources, Keychain) and the UI
  suite run through the Xcode scheme, not in CI. CI runs `swift test` and an
  iOS SDK cross-build only.

## Navigation

- iPhone defaults to Overview, Transactions, Accounts, and More. Up to four
  destinations are user-selectable and reorderable; More stays fixed.
- iPad uses `NavigationSplitView`; the sidebar lists every destination and keeps
  its visibility across selection changes.
- BQL, Currencies, Imports, and Categories live in iPhone More and in the iPad
  sidebar.
- With a local ledger, 账本助手 is the button beside the iPhone tab bar: on iOS 26
  it takes the tab bar's search role (prominent with the iOS 27 SDK), which the
  system detaches into a floating glass button; earlier versions get a trailing
  助手 tab item. Tapping it never switches tabs; it opens the assistant as a
  full-height sheet without the tab bar, so the composer sits at the bottom of
  the screen, with a close button in its header. Closing the sheet keeps the
  conversation and lets a running reply finish; reopening shows it. Shortcuts,
  Siri, notifications, quick actions, `ledger://agent` links and a restored
  agent page open the same sheet, a question carried along as before. On iPad
  the assistant stays a sidebar page.
- Whole-ledger search is an ordinary destination: it can be chosen as a tab and
  otherwise opens from 更多's 账本工具. With a remote ledger, where the assistant
  doesn't run, search keeps the floating button (and a trailing 搜索 tab item
  before iOS 26), and a 搜索 tab chosen for the bar isn't drawn a second time.
  A tab list saved with 助手 as a tab shows 搜索 in its place. A link in an
  answer that opens a sheet (a day's transactions) or a quick entry closes the
  assistant first and appears once it has gone.
- Financial writes keep the shared preview, canonical workspace validation,
  confirmation, and rollback boundaries. Nothing writes a ledger without
  canonical validation of the whole workspace.
