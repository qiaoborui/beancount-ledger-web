承接第一批的六页与关键浮层，这里补齐应用里其余的用户可见界面。同一套语言：色度只留给 --in 与 --out 两个相反方向，其余全是四个明度的墨；行高靠明度与字重拉开层次，不用卡片、不用投影；IBM Plex Mono 只出现在账户路径与 beancount 源码上。

双线（.settle）这一批出现了三次，都是同一件事：一列数字已经封闭并核对通过——向导最后一步的期初结余、单账户对账的断言、导入复核的合计。

账本库与开账

应用进入的第一个界面。它不是账本，是账本的目录——所以这里一个金额也没有。开账向导是本批最重的一屏：它把一个 beancount 仓库的创建过程，翻译成勾选、填数、然后看着净值结平。

搜索与分类

两个查询界面：一个是横向找任何东西，一个是纵向看一棵账户树。搜索结果按类型分节，不混排；分类管理里 已停用 的账户用一条细标签表示，不用彩色胶囊。

待整理与对账

应用的清账台。待整理收件箱收集"记了但没记全"的流水，对账工作台把账面余额和现实对上。两屏都在同一件事实上工作：一笔分录的两侧是否同时成立。

存储、设置与解锁

表单和设置是唯一允许成组的地方——因此这里的行不再靠分隔线，而是靠 .band 的浅底把它们框在一起。冲突解决是这批里唯一一屏要求用户做取舍的界面，所以它把三个选项摊开写清楚，不用红色。

系统浮层与扩展

灵动岛胶囊是全应用唯一一处允许圆角与深色实底的地方——因为它不是我们的界面，是系统的。小组件同样：它借用系统容器，只把自己的排版规则带过去。

深色

同一套层级，换一组明度。深色下 --in 与 --out 需要提亮才够对比——#4fbfab 与 #cf7a52 是它们在暗底上的形态，而不是浅色值加了透明度。双线在深色下用 --ink，因此依然是最重的一条线。
