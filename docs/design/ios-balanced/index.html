Balanced — 复式记账的等式，就是界面本身

这一版不再把余额做成「大数字 + 小标签」，而是把记账本身的结构端上来：资产 − 负债 = 净值、期初 + 净结余 = 期末，用账页页脚的方式逐行写出来再划线合计。数字是可以被核对的，所以它必须看起来可以被核对。

颜色是配给的。整屏只有墨色，唯一带颜色的是钱的两个方向——进项深青、出项赭红——并且只出现在成对的汇总里；流水行里的金额一律墨色，只有收入带上 + 号并被标记。支出是底色，收入是被标出的少数。

概览

净结余用两块结算区承担：上面是资产负债的结算，下面是本期收支的结算，两块都以一条实线合计收尾。留存率紧随其后,用一条按比例分段的横条表示「收入里有多少留下、多少花掉」——它不是图表，是一次相减的结果。

流水

金额按日聚合成一条日合计——这是对账时真正要核对的数字。支出行保持墨色，收入行带 + 并着色；转账既不进收入也不进支出，所以它不着色，只用等宽的账户路径画出钱的走向。筛选计数直接写在标签上，切到哪一类还剩几笔，不用点进去才知道。

收支分析

分析页不另起一套视觉。指标用带线的四格，图表是同一套线的延长：支出柱用出项色、收入柱用墨色，因为收入是那个需要被标出的少数。每张图下面都跟一行「查看数据」——图是给眼睛的，数字是给核对的。

资产分析

资产页的净值同样用结算区呈现，但头部多一行日期契约：这是某一时点的快照，不是区间累计。资产的占比条直接由账户组金额生成，所以任何一段的宽度都等于那一组在总资产里的权重——它既是装饰，也是读数。

账户

这里是「资产负债表」这一页账本的正面。顶部是带日期的结算区，下面按账户组展开——展开后每一条都带完整的等宽账户路径，因为真正写进 main.bean 的是路径而不是别名。负债行单独用出项色，不是给数字化妆，是因为它的符号方向确实是负的。

更多

去掉了编号页眉和图标列——那些编号不是顺序，只是装饰。分组用一条淡色小标题，行高保持在 52pt 以上，右侧直接显示该行当前的值（本地/远端、订阅状态、待处理条数），不用点进去才知道是什么状态。

关键浮层

浮层沿用同一套字体、圆角和墨色，不另起视觉。记一笔的浮层里实打实给出将写入文件的源码预览——这是这个 app 的底气所在：在按下确认之前，你看到的就是会被追加进 .bean 的那几行。

空态与异常

空态不是一句「暂无数据」就完事——它得说清楚为什么空、下一步做什么。异常态同样给出可执行的路径，而不是一句道歉。
