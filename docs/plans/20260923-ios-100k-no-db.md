## Freshness/security

First handle iteration retains existing source-content/symlink validation (including same-size/same-mtime edits) instead of trusting UUID/mtime alone. This leaves O(source bytes) scan cost, but avoids stale-accounting regressions. Removing repeated source scans is a separate profiled step requiring controlled immutable generation ownership and proven invalidation across import/sync/editor, not an untested optimization bundled with handles. Cursor+handle includes revision and cannot cross ledger boundaries.

Stream/model cache/schema are disposable; .bean source layout unchanged. Lock gates new reads, invalidates result publication and closes/releases sensitive working state following existing privacy policy. Runtime files excluded from source exports/Git/backup where policy requires. Failure/cancel/disk-full leaves old committed revision and confirmed-source semantics unchanged. Public tests/docs only synthetic data. No automatic install into a personal physical-device app container.

## Risk and stop conditions

Most fragile assumption: Python booking plus compact Go model and limited generation overlap fit the target phone. If not, stop claiming capacity; do not increase limits/drop precision/skip validation. Present separate no-DB disk-record/offset-index or canonical-engine redesign proposal rather than silently introducing custom storage or SQLite. Also measure temporary export disk and writer copies; noDB is not no disk.

Minimal mitigation is pagination+B1/B2 but that alone cannot solve first-load request size; handle registration with full JSON likewise fails. Streamed registration+compact model is chosen as the least storage-redesign approach consistent with100k goals. Preserve explicit rollback to legacy only for supported small ledgers;100k legacy incompatibility must be reported.
