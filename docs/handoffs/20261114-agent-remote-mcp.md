## Goal

Let the user add remote MCP servers (Streamable HTTP only; an iOS app can
spawn no stdio server) whose tools join the ledger assistant's own, with
per-server tokens in the Keychain, a settings page, and a native probe.

## Decisions

- **Tool names use the server id**: `mcp__<id>__<tool>`, both parts reduced to
  `[a-zA-Z0-9_-]` and the whole name capped at 64 characters, with numeric
  suffixes on a collision. The id is generated by the app (`8` lowercase hex
  characters) and is already unique, so a name never depends on a Chinese name
  that sanitizes to nothing; the server's own name goes into the tool
  description ("由用户接入的外部 MCP 服务器「…」提供") and the step row.
- **Unreachable servers are reported before the question, not in the system
  prompt.** A per-turn failure list in the system prompt would break the
  provider's cached prefix on every failure; the turn instead prefixes the
  question with a `（系统提示：连不上 MCP 服务器「…」…）` note, the same way an
  attachment announcement is prefixed. The static MCP rules are appended to the
  system prompt (after the ledger/attachment/history prompts, before
  `remembered.prompt()`), so the prefix stays cacheable.
- **The server-to-client GET stream stays closed** (`OpenGetStream: false`): the
  loop handles no server notification, and an open stream would hold a
  connection and a goroutine for the whole turn. Tools are listed with one
  `tools/list` per server at the start of the turn.
- **Validation vs. unreachable**: a refused URL or header is a request the shell
  should not have sent, so the turn fails with the reason; anything that only
  fails to connect is a note. Limits: 8 servers, 40 tools per server, 80 in all;
  a cut is stated in the note.
- **Plain http is allowed only for `localhost`/`*.localhost`, `*.local` (mDNS)
  and private, loopback, link-local or unspecified IP literals.** Names are not
  resolved: a name that happens to resolve privately is no reason to send a
  token in clear text. URLs with credentials, a query or a fragment are refused,
  matching `customModel`'s rule for a custom endpoint.
- **Schemas** go through `objectParameters` (so `required` is never `null` and
  `properties` is always an object) and keep the server's other top-level
  members, `additionalProperties` included: a remote tool may take arguments
  nobody enumerated, so the package's own `additionalProperties: false` is
  dropped.
- **Results** go through `mcp.ToLLMContent` (text, images, embedded resources,
  `structuredContent` as text), text is joined and cut at 20000 runes with a
  stated tail, images are sent only to a model that can see them (otherwise a
  placeholder line), and `isError` becomes the tool's error result.
- **A turn's HTTP client is the fetch** (`network.client` from `transport.go`),
  so the stop button, the connect timeout and the per-call timeout all apply;
  clients are closed concurrently when the turn ends.
- **Swift**: the list lives in `UserDefaults`, each token in the Keychain under
  the model-key service with account `mcp.<id>`, behind a small
  `LedgerAgentMCPTokenStore` protocol so tests use an in-memory store.
  `LedgerAgentMCPSettings` owns the list; `LedgerAgentMCPServerIndex` is a
  lock-guarded, nonisolated index of id → display name, because
  `LedgerAgentToolCall.title` is computed outside the main actor and must show
  the server's name in a step row. Only `Authorization: Bearer <token>` is sent
  as a header.
- Onboarding (AI 开账) refuses a request that carries MCP servers, like it
  refuses a ledger, scratch copy, memory or attachments.
- `MCPProbeJSON` is a normal exported function of `server/mobileagent`, which
  `scripts/build-ledgercore-xcframework.sh` binds whole, so it reaches
  LedgerCore with no build-script change.

  reading the surrounding code; `swift test`, the LedgerCore xcframework build
  and the Xcode app check are left to CI (Mac runner). Not tested: a real MCP
  server, a signed build, the settings page on a device.

## Remaining

1. CI `Gate` (Swift compile + tests) is the real check for the Swift side.
2. The settings page is not wired into `LedgerAgentSettingsView` (A owns that
   struct): the owner connects `LedgerAgentMCPView` from the new 能力 section.
3. Only `Authorization: Bearer` is supported; a server that wants another header
   name would need an editable header list.
