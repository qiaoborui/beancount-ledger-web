# 支付宝账单的列与特殊情况

## 列名

交易明细 CSV 的表头通常有这些列（导出时列的顺序和叫法可能略有不同，以 `read_attachment` 看到的为准）：

| 列 | 含义 | 用在哪 |
|---|---|---|
| 交易时间 | 支付或入账时间，形如 2026-10-05 12:31:08 | `dateColumn` |
| 交易分类 | 支付宝自己的分类，如 餐饮美食、交通出行 | 选支出账户时的参考 |
| 交易对方 | 商户或对方名称 | `descriptionColumns`、payee |
| 商品说明 | 买了什么 | `descriptionColumns`、narration |
| 收/支 | 支出、收入、不计收支、空 | `directionColumn` |
| 金额 | 正数，单位元，没有符号 | `amountColumn` |
| 收/付款方式 | 余额、余额宝、招商银行信用卡、网商银行储蓄卡等 | 决定从哪个账户走 |
| 交易状态 | 交易成功、交易关闭、退款成功等 | 过滤 |
| 交易订单号 | 支付宝订单号 | 判断是不是同一笔 |

## 付款方式对应账户

先用 `get_accounts` 看账本里实际有哪些账户，再按这个规律对应：

- 余额、余额宝 → 账本里的支付宝资产账户，例如 `Assets:CN:Alipay` 或 `Assets:CN:Alipay:Balance`；余额和余额宝在账本里没分开就记同一个。
- 招商银行信用卡、其他信用卡 → `Liabilities:` 下对应的卡。
- 储蓄卡（招商银行储蓄卡、网商银行储蓄卡等）→ `Assets:` 下对应的银行账户。
- 花呗 → 账本里有专门的花呗负债账户才记，否则跳过并告诉用户。
- 亲情卡、代付、红包 → 看账本的记法；没有就先问用户记给谁。

## 特殊情况

- **不计收支**：余额宝和基金申购、账户之间的划转。默认不记，问用户要不要记；要记就是两个资产账户之间的转账，金额对得上余额变化。
- **基金申购 9.99 实付 10.00**：账本里如果按 10.00 记基金，差额 0.01 记到收入或优惠科目，不要只记 9.99。
- **退款**：退款日期通常晚于消费日期，按原商户和金额找出原消费，冲销或记一条负支出；不要和原消费直接对消成零。
- **交易关闭、退款成功但金额为 0**：跳过。
- **同一商户同一天同金额两笔**：两笔真实消费，都记。
- **余额校验**：用户给支付宝 App 的余额时，用 `run_bql` 或 `get_ledger_summary` 算账本里该账户的余额来比；差一点先找是不是漏了某天，别直接调平。
