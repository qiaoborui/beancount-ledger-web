# 导入微信支付账单

用户上传微信支付账单（XLSX，或问「微信的账对上了吗」）时按这个流程走。手工记的账优先，账单用来找缺漏、核对零钱余额。

1. **找到账单**：`list_attachments`。没有就先请用户导出（微信：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账，得到一个 XLSX）。XLSX 里前面几行是导出说明，表头不一定在第一行，用 `read_attachment` 看清楚。

2. **看表头和期间**：`read_attachment` 读前几十行，记下表头行号（对账时当 `headerRow`）、日期范围、有没有「收/支」「当前状态」列。微信账单常见的列是：交易时间、交易类型、交易对方、商品、收/支、金额(元)、支付方式、当前状态、交易单号、商户单号。

3. **确认账户**：`get_accounts`。「支付方式」是零钱、零钱通就走微信零钱资产账户（例如 `Assets:CN:Wechat`），信用卡走 `Liabilities:` 下对应的卡，储蓄卡走 `Assets:` 下对应的银行账户。对不上号的先问用户。

4. **对账**：`reconcile_attachment`，一个付款方式对一次：
   - `id`、`sheet`、`headerRow` 用第 2 步的；
   - `dateColumn` 填「交易时间」，`amountColumn` 填「金额(元)」，`directionColumn` 填「收/支」；
   - `descriptionColumns` 填「交易对方」和「商品」；
   - `accounts` 填第 3 步确认的账户，`start`、`end` 用账单期间。
   结果里提示方向可能反了就换 `amountSign` 再对一次。

5. **只补账本缺的**：账本里已经有的不动。留意这几类容易重复：
   - 手工记的一笔总额，账单里拆成几笔（例如收租 1062 元，账单里三笔 354）；
   - 深夜支付的，账单日期比手工记的晚一天；
   - 同一天同金额的重复支付（可能是真的两笔，先看商户）；
   - 退款在另一天单独出现。
   拿不准就用 `ask_user` 问一句「账本里 5-02 晚餐 180 和账单里 5-03 这家 180 是同一笔吗」。

6. **写进草稿**：`list_files`（pattern `transactions/**/*.bean`）和 `read_file` 找到当月流水文件，不存在就新建并在入口文件 `include`。按日期顺序追加，`edit_file` 把该月最后一条交易当作 old_string 的结尾。每笔支出账户写正数、付款账户写负数，同币种合计为零，金额两位小数，payee 用交易对方，narration 用商品，平台 `wechat` 放 metadata。

7. **跳过这些**：当前状态是「已全额退款」「已转账」但其实是内部划转的、0 元、方向是「/」的（不计收支，例如零钱通转入转出，先问用户要不要记）、已撤销的。

8. **校验**：`bean_check`，改到通过。

9. **归档原件**：`archive_statement`，`provider` 填 `wechat`，`dateStart`、`dateEnd` 填账单覆盖的起止日。

10. **汇报**：对上多少笔、账单合计、账本合计、差额；补了哪几笔；哪些没处理。差额去找真实缺漏，不要加调平科目。用户给了微信零钱余额时用 `run_bql` 算账本余额来比。
