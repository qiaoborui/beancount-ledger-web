# 记账

用户说「记一笔」「昨天星巴克 38 招行信用卡」「发工资了」这类话时用这个技能。目标是一步到位：查账户、写进草稿、校验通过就写入，不要来回确认。

1. **先分意图**，一句话可能有好几笔：
   - 支出：花钱，支出账户正数、付款账户负数；
   - 收入：进钱，收款账户正数、收入账户负数；
   - 转账：两个自己的账户之间，转出负数、转入正数；
   - 还款：还信用卡或还别人的钱，负债账户正数、付款账户负数；
   - 报销：先记支出，报销到账时记收入或冲减那笔支出，保留原来的用途；
   - 退款：商户退回，收款账户正数、原支出账户负数；
   - 一笔多分类：一次付款买了不同类别的东西，一条交易里写多条支出分录，合计等于付款金额。
   各自独立记，不要把几笔消费合成一条「杂项」。

2. **日期**：用户说了就用他说的（「昨天」「上周五」按当前日期换算），没说就是今天。日期写 `YYYY-MM-DD`，记在它所属的月份文件里。

3. **账户**：`get_accounts` 查已开户的账户，只用账本里已有的。分类拿不准（同一个商户以前记在哪个账户、这笔算餐饮还是日用）先 `search_transactions` 或 `run_bql` 看以前的记法；还是拿不准就 `ask_user` 问一个具体问题，不要猜，也不要为了这笔新建账户——用户明确要求才新建。

4. **金额**：元为单位，两位小数，同一币种的分录合计为零。外币按账本里的记法处理，不知道就用 `ask_user` 问。

5. **写进草稿**：
   - `list_files`（pattern `transactions/**/*.bean`）看有没有当月文件，`read_file` 入口文件确认它被 `include`；
   - 没有当月文件就 `write_file` 新建，内容从 `include "transactions/YYYY/MM.bean"` 那行开始补；
   - 追加时 `read_file` 看该月最后一条交易，`edit_file` 用它的最后两行当 old_string，新交易接在后面；
   - 格式：

   ```
   2026-10-05 * "瑞幸咖啡" "生椰拿铁"
     platform: "alipay"
     Expenses:Food:Coffee   18.00 CNY
     Assets:CN:Alipay       -18.00 CNY
   ```

   payee 写商户或对方，narration 写买了什么；平台、渠道、和谁一起、什么场合放 metadata（键用小写英文：`platform`、`channel`、`person`、`event`、`purpose`）；tags 只给跨月份的主题用（`trip-2026-shanghai`、`renovation`），不要给商户打 tag。

6. **校验**：`bean_check`，有错按报错改到通过。校验通过后 App 会按写入设置处理（默认直接写入并可以撤销）；校验失败、改动很大或账本在别处改过时，App 会停下来让用户确认，这时在回答里说清楚卡在哪。

7. **回答**：一两句话说记了什么（日期、商户、金额、账户），不要贴整段分录，也不要说「已写入」除非这一轮确实写入了。记了几笔就说几笔。

拿不准就问一个具体的问题（「这 180 是记餐饮还是日用？」），不要一次列一串选项让用户挑。
